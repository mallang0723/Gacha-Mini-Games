# 가챠 미니게임 · 어디서나

마리나라에서 채팅을 기다리거나 쉬는 동안 🎮 버튼으로 즐기는 개인 확장입니다. 원본 12개 게임과 가챠포지 생성 화면 표시를 재사용하고, 화면 어디서나 여는 패널과 RP 생성 대기 자동 열기를 추가했습니다.

원작자: **lemonpie601** · 원본: https://github.com/lemonpie601/Gacha-Mini-Games  
기반 버전: **v1.3.1**, 커밋 `79fc380dcad85ddb7f0fa469c5f84bb0d7090be4`  
원작자 게시글 허락 문구(작업 BRIEF 제공): **“마개조 허용(링크만 남겨주세용)”**. 원본 링크와 저자 표기를 유지합니다. 이 결과물은 비공식 파생판이며 원작자의 공식 배포판이 아닙니다. 출처·변경 사항은 [NOTICE](NOTICE)에 있습니다.

## 설치

1. [gacha_minigames_me.personal-extension.zip](gacha_minigames_me.personal-extension.zip)을 내려받습니다. 압축을 풀 필요는 없습니다.
2. 마리나라의 **개인 확장 관리 → ZIP 가져오기**에서 파일을 선택합니다.
3. 확장 이름 **가챠 미니게임 · 어디서나**와 `full_page_access` 권한을 확인하고 활성화합니다. 가져오기 기본값은 비활성입니다.
4. 오른쪽 가장자리 🎮 버튼을 눌러 게임을 엽니다.

원본 확장을 따로 설치할 필요가 없습니다. 원본과 같이 설치되어도 `window.__GF_MINIGAMES_EXTENSION`을 통해 가챠포지 표시 담당을 하나로 유지합니다. 원본이 나중에 실행될 때도 어디서나 버튼은 남습니다. 이 확장을 비활성화하면 자체 UI·구독·타이머·이벤트가 해제됩니다. 원본만 남기는 경우 원본 확장을 다시 활성화하면 가챠포지 표시 담당을 다시 등록할 수 있습니다.

## 사용과 설정

- 🎮 버튼: 열기/닫기. 오른쪽 세로줄을 따라 위아래로만 드래그할 수 있습니다. **0.7초 길게 누르기** 또는 설정의 **버튼 위치 초기화**로 기본 높이로 돌아갑니다. 키보드로 버튼에 포커스한 뒤 ↑/↓로 이동, Home으로 초기화할 수도 있습니다.
- 패널의 **설정 → RP 생성 2.5초 뒤 자동 열기**: 기본 **켬**. 짧은 생성에서는 열리지 않습니다. 자동으로 열릴 때 채팅 입력 포커스를 가져오지 않습니다.
- **응답 도착 시 자동 닫기**: 기본 **끔**. 기본 동작은 “응답 도착” 토스트와 **닫기 / 계속하기** 선택을 표시하면서 게임을 유지하는 것입니다. 켜면 응답 도착 시 패널을 닫습니다.
- 닫기 버튼이나 패널 안에서 Escape를 눌러 닫습니다. 수동으로 닫은 패널은 같은 생성 중에 다시 자동으로 열리지 않습니다.
- 방향키·숫자키 등은 해당 게임에 포커스가 있을 때만 처리합니다. 채팅의 textarea/input/contenteditable 입력은 보호합니다. 자동으로 열린 패널은 게임을 직접 클릭한 뒤 키보드로 조작하세요.
- 게임을 접거나 패널을 닫아도 현재 확장 인스턴스 안의 게임 상태는 유지합니다. 화면 갱신 타이머는 숨김 중 정지합니다. 원본 게임별 시간 규칙은 유지하므로 모든 게임의 경과 시간이 일괄 정지되는 것은 아닙니다. 짝 맞추기 미완성 카드는 접고, 레시피는 다시 열 때 현재 순서를 재생합니다. 페이지 새로고침 후에는 최고 기록만 남습니다.
- 설정·버튼 높이·최고 기록은 이 브라우저의 localStorage에 저장합니다. 저장소가 차단되어도 현재 세션에서 사용할 수 있습니다.

포함 게임: 지뢰찾기, 사과 상자, 2048, 짝 맞추기, 쿠키 가게, 디저트 핀볼, 비스킷 벽돌깨기, 스네이크, 딸기 우유 레시피, 초코칩 터뜨리기, 꽃밭 퍼즐, 별 밝히기.

## 화면·테마·연결

말랑의 `data-gfx-preset`와 `--gfx-card/line/text/ink/pick/accent` 색을 따라가며 없으면 크림 기본색을 씁니다. 시스템 폰트만 사용합니다. 공유 SD 이미지는 이미 메모리에 있는 같은 출처 blob 또는 PNG/JPEG/GIF/WebP data 이미지에 한해 사용하고, 원격 URL은 기본 과일 그림으로 대체합니다.

360px 폭에서 패널은 화면 안에 들어오도록 설계했고, 게임 목록은 가로로 스크롤합니다. 게임 버튼은 최소 44px입니다. 지뢰찾기 등 칸이 많은 보드는 터치 크기를 유지하기 위해 **보드 안을 가로로 스크롤**합니다. 큰 화면에서는 원본처럼 게임 옆에 목록이 나옵니다. 실제 기기에서의 크기·터치 검증 상태는 [REPORT.md](REPORT.md)를 확인하세요.

RP 감지는 `globalThis.__MARINARA_HOST__.stores.chat`의 `isStreaming`/`streamingChatId` 구독이 우선입니다. 스토어가 없으면 활성 스토어의 `activeChatId`, 또는 URL의 `chatId`/`chat` 쿼리와 `/chat/:id`, `/chats/:id` 경로(hash 경로 포함)로 채팅을 찾아 `marinara.fetch`로 **같은 출처의 `GET /api/generate/status/:chatId`만 1초 간격으로 확인**합니다. ID를 얻지 못하면 수동 게임만 사용할 수 있으며 설정에 감지 상태가 표시됩니다. 다른 채팅으로 이동하면 진행 중인 폴백 요청을 취소합니다. 상태 조회 오류는 응답 도착으로 오인하지 않습니다. 나중에 스토어가 나타나면 구독으로 전환합니다.

모델 호출, 생성·취소 요청, 채팅 내용 읽기·수정, 외부 네트워크 요청, fetch 몽키패치는 없습니다. `crypto.randomUUID`에 의존하지 않아 비보안 HTTP에서도 사용할 수 있습니다. 가챠포지는 원본 기준대로 실제 생성 상태가 2.5초 지속될 때만 표시하고, 부팅·이미 작성된 챕터 읽기는 제외합니다.

## 개발·검증

모든 소스·빌드·테스트·문서는 `anywhere/` 안에 있습니다. 저장소 루트 원본 파일은 변경하지 않습니다. 기존 개인 확장 프로젝트의 `src/`, `scripts/build.mjs`, Node 테스트, 결정적 ZIP 패턴을 따릅니다. 런타임·빌드·ZIP 생성에는 외부 패키지가 필요 없습니다. 테스트에는 jsdom, 선택적 브라우저 검사에는 Playwright가 필요합니다.

```sh
cd anywhere
npm install --ignore-scripts
npm run verify:original
npm run build
npm test
npm run package
npm run qa:browser
```

검증 환경: Node 26.7.0. 설치 명령은 개발 의존성을 준비하기 위한 선택적 절차이며, 확장 실행이나 빌드가 패키지 서버에 접속하지는 않습니다. 현재 작업에서는 패키지를 내려받지 않고 이미 설치된 모듈을 읽기 전용으로 재사용했습니다. 오프라인 재사용 시에는 다음과 같이 모듈 경로를 지정할 수 있습니다.

```sh
ANYWHERE_NODE_MODULES=/path/to/existing/node_modules npm test
ANYWHERE_NODE_MODULES=/path/to/existing/node_modules \
  ANYWHERE_CHROMIUM=/path/to/chrome-headless-shell npm run qa:browser
```

`ORIGINAL.sha256`은 루트 `extension.js`의 고정 SHA-256입니다. 빌드 때 매번 대조하고, `/* Mounting: the games sit inside` 앵커가 정확히 한 번인지 확인한 뒤 원본의 게임 부분에 어댑터를 접합합니다. 파생본의 안전성·정리 패치도 각각 정확히 한 번만 적용합니다. 원본 변경을 감지하면 빌드를 중단합니다. `qa/patches.json`에 적용 패치, `qa/package.json`에 ZIP과 포함 파일 해시가 기록됩니다.

생성물은 `dist/manifest.json`, `dist/extension.js`, 그리고 설치 ZIP입니다. ZIP 루트에는 `manifest.json`, `extension.js`, `README.md`, `NOTICE` 네 파일만 들어갑니다. ZIP 안의 README에서 개발 파일이나 ZIP 자체를 가리키는 링크는 저장소의 `anywhere/`에서 확인하세요.
